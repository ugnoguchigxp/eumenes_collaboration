# 共同作業の評価

固定試験、実モデルの意味評価、製品UI・DBの受入を分けます。`bun run eval:check` は課題の構造と分割だけを検査し、意味品質の成功を表しません。

0.3.0の封印評価は、30課題・2モデルで実施済みです。旧版1回と候補3回の多数決という当時の条件と、自動判定・小標本の限界は [実施記録](../spec/improvement-design-2026-11-06.md) にあります。候補の課題単位の合格は28/30、29/30でした。統計的な優越性や、製品での人の受入を示す結果ではありません。

課題・protocol・原記録は [保管資料](results/2026-11-06/holdout-v2/manifest.json) から照合できます。次のコマンドは、個人の一時フォルダーや認証・課金なしで再集計します。

```sh
bun eval/archive.ts eval/results/2026-11-06/holdout-v2
```

新規評価は [protocol v3](protocol-v3.json) を基に、課題hash・反復・実際のモデル・予算・採否条件を凍結してから登録します。現在のv3はdraftです。旧新版の反復は同じにし、単発の対話成功率を主指標にします。各ターンの状態も採点し、後で訂正された誤確定を見落としません。課題の意味の判断にはLLMと人の確認を使い、出所・権限・版の不正はコードで拒否します。

保管するのは合成課題の証拠です。製品の会話原文・秘密・認証・接続設定をコピーしません。UIの表示、Pipelineの動作、外部agentの仕事は、それぞれ実際の経路で受入を行った範囲だけを検証済みとします。CIは実施しません。
