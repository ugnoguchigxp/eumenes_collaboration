# Quick評価の上限を120秒に延長した再測定

追加した難問3課題で、Evaluatorのみと両方ありを各2回実行した。Luna 6.0 `low`、Quick、課題と採点基準は前回と同じ。評価サービスと評価用モデル呼び出しの上限をともに120秒にした。通常返答・SKILL・成果物作成は各60秒。評価が120秒かかる場合も作成時間が残るよう、評価を利用可能にした試行全体の上限を240秒とした。Web検索を追加する前の測定。 [事前登録](registration.json) · [60秒との比較](timeout-comparison.json)

| 条件 | 正答行 60秒→120秒 | 完了時間の中央値 60秒→120秒 | 評価完了／起動 60秒→120秒 |
| --- | ---: | ---: | ---: |
| Evaluatorのみ | 18/48 → 20/48 | 45.61秒 → 40.24秒 | 1/3 → 1/3 |
| 両方あり | 24/48 → 21/48 | 74.10秒 → 33.15秒 | 1/4 → 1/3 |

全12試行で成果物は完成した。評価の時間切れは前回2件、今回は0件。評価結果が作成担当に届いたのは両測定とも2件。60秒を超えた公開承認の評価は67.99秒で返り、確認範囲の不足で未完了となった。両方ありの中央値の短縮には、評価が起動しなかった試行が2件から3件に増えたことも影響する。各2回の独立した測定で、上限延長による正答率の改善は確認できなかった。 [集計](summary.json) · [採点](grades.json) · [試行記録](raw.jsonl)
