# Skill Smithを使うUI共同制作の隔離実測

2026年11月11日。合成の予約フォームを使い、通常の返答が確定してから、Evaluatorによる定義の評価と、Context Still MCPで取得した手順を使った確認票の作成を並行して実行した。Context Stillには合成の手順を1件登録し、公開MCPハンドラーを同一プロセス内で呼んだ。モデルは `gpt-6.1-sol`、推論設定は `low`。ログイン済みのCodexサブスクリプションを使用した。 [実行方法](../../../../example/proactive/README.md)

## 受入試験の結果

| 計測区間 | 時間 |
| --- | ---: |
| 利用者への通常返答 | 12.44秒 |
| 背景評価の開始から完了まで | 11.14秒 |
| スキル作業の開始から配達まで | 67.00秒 |
| スキル配達後の成果物作成 | 6.77秒 |

Evaluatorは版1の定義の `/title` で「予約フォーム」と「申込フォーム」の不一致を特定した。Skill SmithはContext Still資料の版1を再照合し、元の手順にだけある「運用照合キー RZ-47」を含むスキルを配達した。作業担当はその欄を確認票の先頭に入れ、タイトルの不一致、部署は必須、備考は任意を記載した。 [通過した試行と確認票](live-complete.json)

通過した試行は実モデル6呼び出しで、入力95,332、出力2,953トークンを記録した。先行試行を含む実測は計23呼び出し。通過試行でContext StillのMCPに対して行った7操作の合計は、プロセス内で約7.9ミリ秒だった。既存試験を含めて199件が通過し、型検査も通過した。

今回の実測は明示的に評価を依頼した合成ケース1件。外部のMCPサーバーへの通信時間、スキルなしとの品質差、自発的な背景評価の選択率は未測定。

## 先行試行

1. 通常返答が既存の文数上限を超えた。モデルに2文以内を明示し、同じ検査基準で再試験した。 [初回の結果](live-first.json)
2. 通常返答とEvaluatorが完了した。Skill Smithは追加情報が必要と判定した。確認票の受入条件と作品の合意条件を区別し、作品の現在版、確定条件、ユーザーの依頼をSkill Smithに資料として渡す形に改めた。 [2回目の結果](live-second.json)
3. スキルの配達と確認票の生成まで完了した。確認票はタイトルの差異と各項目の設定を含んだ。手順にだけある定型の照合欄が成果物に入らなかったため、スキルの必須項目・表記・順番も照合するよう作業担当に指示し、配達本文と成果物の双方を試験記録に残すようにした。 [3回目の結果](live-third.json)
4. 配達本文にも照合欄がなかったため、欠落はSkill Smithの生成段階と特定した。ユーザーの依頼と両立する、採用した手順の必須項目・表記・順番をスキルに保持することを生成時の受入条件に加えた。 [4回目の結果](live-fourth.json)
