# Skill Smithの資料取得と審査を含む改修後の再測定

[最初の改修後試験](../proactive-luna-low-revised/README.md)と同じ合成6課題で、現行相当と支援ありを各1回実行した。全工程で `gpt-6-luna` の `low` を使用した。課題、採点基準、1回60秒・1試行180秒・支援あり最大6回の呼び出し枠は前回と同じ。 [事前登録](registration.json)

2文を超えた通常返答は文数を記録し、成果物作成を続ける。支援ありでは、MCPの手順の題名を選択の参考に提示し、作業対象と成果物の目的の両方に適用できそうな手順をモデルが選ぶ。適用候補の本文は既存の `disclose` でまとめて取得し、生成と意味審査の枠を残す。採用する手順は既存の版確認と審査を経て配達する。Evaluatorの対象は、元の依頼と確定条件に加え、定義の各レコードを指す個別のJSON Pointerで構成する。

通常返答と成果物の時間は依頼開始を起点とする。成果物の得点は方式名を伏せた各課題4条件で、手順の定型欄は別指標。前回と各1反復の比較であり、差を単一の改修に帰属させるには反復が必要。

文数超過の2件は、どちらも公開判断の引継ぎ課題で、それぞれ13文と10文だった。成果物は両方とも確定した。

Evaluatorは有用と見込んだ3件中2件で起動した。取消通知では4分岐を確認し、前回見落とした未取消時の誤送信を含む違反2件を指摘した。適合する2分岐も違反と判定し、最終成果物には分岐aを保留とする誤りが残った。最初の改修後試験では同じ確認範囲で誤指摘なく2件を検出した。公開判断では評価が未完了だったため成果物の参考資料に採用しなかった。

Skill Smithは有用と見込んだ3件すべてで自発的に選ばれ、取消通知でも追加で選ばれた。配達成功は0/4件。機材貸出と公開判断では本文の定型欄までモデルが確認したが、機材貸出では利用できない初期化ツールを前提にし、公開判断では条件不足と判断した。欠品は3回の枠のうち2回使用した時点でモデルが審査枠不足を申告した。取消通知には適用できる候補がなかった。スキルが届かなかった試行も元資料から成果物を作成した。
