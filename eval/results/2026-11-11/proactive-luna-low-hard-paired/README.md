# 追加3課題の支援あり・なし比較

[難易度を校正した3課題](../proactive-luna-low-hard/README.md)を、支援なしと支援ありで各2回、計12試行実行した。両方式とも、隔離環境からCodexの契約経路を使い、`gpt-6-luna` の推論設定を `low` に固定した。課題と実行コードのハッシュは校正時と一致する。各組の実行順は課題ごとに入れ替え、最大2組を並行実行した。 [事前登録](registration.json) · [入力と正解](cases.mjs)

支援ありでは、EvaluatorとSkill Smithを利用可能にし、制作担当が自発的に選択した場合に起動する。Evaluatorの完了済みの指摘と、Skill Smithが依存版を照合して配達した手順を、成果物の作成担当が受け取る。主比較には今回測った支援なしを使い、前回の校正値は参考にした。

1行の判定、根拠IDや引当内訳、現行との照合がすべて合っていれば正答とした。従来の採点器で方式名を伏せた成果物を採点した後、同一課題・同一反復の行と支援の記録を突き合わせた。この比較は、両方を利用可能にした構成全体を対象とする。

## 指摘と成果物で確認したこと

- **取消通知**。1回目のC-11で、Evaluatorは旧取消の受理ログが現在の取消に紐づかないと指摘した。支援なしは「送信済み」、支援ありは正しい「送信対象」だった。同じ評価でC-16は締切後に受領した取消を有効と誤判定し、その行は成果物でも誤答だった。C-17は有効な受理ログを見落とし、両回とも誤答だった。C-18の2回目は支援なしで正答し、支援ありで誤答した。この回のEvaluatorは未完了で、指摘は作成担当に渡らなかった。
- **欠品引当**。両回でS-01の引当可否、S-05・S-06の不足数が正しくなった。1回目はSkill Smithが基準時刻・仮引当・残数の照合手順を配達し、Evaluatorは時間切れだった。この回では、引当停止中のA2をS-03に使う誤りが残った。2回目はS-03・S-04の引当も正しくなったが、EvaluatorもSkill Smithも選択されなかった。この回の改善は計5行で、全体の純増8行のうち5行を占める。他拠点の最低期限を誤るS-07と、代替品を正しく引き当てられないS-08は両回とも残った。
- **公開承認**。P-01の内容承認の取消を「対象承認なし」と分類する誤りが両回で解消した。2回目はEvaluatorの指摘と成果物の修正が一致した。一方、正しいP-02の「対象承認なし」をEvaluatorが誤って指摘し、成果物でも「内容承認なし」に変わった。両回でSkill Smithの配達は成功したが、P-04の免除終了時刻、P-05の締切後の取消ログ、P-06・P-07の停止連鎖の誤りは残った。

Evaluatorは6試行中5回選択され、完了2回、時間切れ2回、出力の一部が受理されず未完了1回だった。評価の待ち時間は51.4〜60.0秒で、成果物確定の遅れの大きな部分を占めた。Skill Smithは3回選択され、すべて原文の版を照合して配達した。2方式の得点差は観測できたが、支援が起動しなかった試行でも改善があり、同じ課題の2反復から各支援の寄与は特定できない。C-11とP-01の各1行では、作成担当に渡った具体的な指摘と正答が対応した。

## 配達したSKILLの出典と範囲

検証環境のContext Stillには、在庫引当と公開承認の合成手順を各1件登録した。LunaはMCPで取得した本文を読んで1件を選び、Skill Smithの互換経路が原文を `SKILL.md` に整形した。配達記録の3件すべてで、本文と全3手順が元の知識レコードに一致した。選択したContext Stillの参照IDと配達時の依存IDも一致した。既製探索SKILLの日本語版・英語版とは、名前・ハッシュ・本文が異なる。共通の「確認」欄は試験側が付けた。 [登録手順](cases.mjs#L411) · [配達本文](raw.jsonl)

在庫引当では、区分ごとに仮確保し、全量を確保できなければ戻す手順を渡した。公開承認では、版・対象・時刻を確認し、依存先から判断して停止連鎖の途中と末端を記す手順を渡した。どちらも作業に合うが、引当停止中のロットの扱いや、承認ログの受領期限といった判断の細部は作業資料と確定条件に委ねている。この比較で計測したSkill Smithは、登録済み手順の検索・適用判断・再利用・配達。複数の知識を使って手順を補足・合成し、内容を審査する経路は今回の比較に含まれない。
