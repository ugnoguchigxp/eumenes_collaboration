# UI共同制作の現行方式とSteerの隔離試験

2026年11月11日。対象は Eumenes の `binding:ui.studio@5`。現行方式の測定と、Steerの接続確認は別のホストコピーで行った。各試行は一時SQLiteを作成し、Eumenesの試験用HTTP入口を同一プロセス内で呼ぶ。製品のデータベース、設定ファイル、会話を持ち込まず、製品サーバーは操作していない。

## 測定条件

- 本体の確定コミットから作ったアーカイブ、同梱Collaboration、評価課題、実行コードのハッシュを[事前登録](registration.json)に固定した。作業中の本体コピーは別作業のAgencyコードの新旧が混在して起動できなかったため、基準には確定コミットを使用した。
- `ui.compose` の選択は既存の試験用ルーターで固定し、UI担当の推論、作品の編集、条件・出所の保存は現行経路を通す。実モデルは `gpt-6.1-sol`、推論設定は `low`。EumenesのCodex接続を、ログイン済みのChatGPTアカウントで使った。APIキー経由の追加予算は0ドル。正式な基準測定は制作と暫定採点を合計して440モデル呼出しを上限とした。
- 評価用24課題を各2回、最大6対話ずつ実行する。更新後30秒の待機後に、別呼出しのモデル利用者役が判断材料の不足を確認し、必要なら事前に決めた追加発言を一度送る。採点はモデルによる暫定値。自動の担当選択、実ブラウザーの描画、製品負荷、人による採否はこの測定の対象外。待機中に会話へ単独で届いた通知の計数は、この収集コードの対象外。
- [集計スクリプト](summarize.py)は保管した合成課題の記録を読み、課題のハッシュ、登録条件、課題と反復の重複を検査して再集計する。接続確認用の調整課題とSteer試験は、評価用の集計から除く。

## 基準測定の結果

評価用24課題の2反復、計48試行を記録した。45試行で通常ターンが完了し、両方の観測時点の作品と条件を取得した。モデルの暫定判定では、条件充足29/48、追加指示なしで条件充足25/48。先読み準備が役立つ課題では、追加指示なしで条件を満たしたのは2/12、追加指示は7件だった。全体の追加指示は10件。24課題のうち3課題では、反復間で主指標の成否が分かれた。発言受付から返答確定または待機上限までの中央値は21.82秒、p95は33.95秒だった。 [集計結果](summary.json) · [合成課題の原記録](mode-a-holdout.jsonl.gz)

終了しなかった3試行のうち、別作品に切り替える課題は2反復とも `permission_revoked` だった。残る1試行は返答待ちの120秒を超えた。モデル呼出しは登録上限440回に対して161回。タイムアウトした呼出し1回は、試行の書き出し後に取消が確定したため、呼出し数に含め、トークン集計は記録がある160回分とした。サブスクリプション経路の呼出しごとの請求額は取得していない。

## Steerの接続確認

公開コミット `1250b2071392bf54204fda871cd371830713ce45` の `eumenes-steer@0.1.0` を、[ハッシュを固定したTGZ](steer-package.json)からオフライン導入した。ライブラリの型・整形・lintと24試験が通過した。

[試験ホストへの差分](steer-host.patch)では、UI担当の実行IDと世代でInboxを開き、試験側が保存した出所参照を既存の次回推論で取得する。実行・会話・セッション・世代、資料の版と期限を照合する。取得した補足だけを動的な資料として渡し、推論の応答が確認できれば確定する。結果が不明な場合は再送せず、実行終了時にInboxを閉じる。

[固定試験](steer-test.log)は2件とも通過した。次の推論で有効な参照だけを一度受け取り、重複、旧版、別会話、異なる世代を排除した。推論中に出所が更新された場合は、その出力を保存しなかった。[実モデル確認](steer-live.json)では、最初の文書操作を固定し、その次の推論にだけ版2の記録を渡した。モデルは記録の確認番号 `KIOSK-27` を返し、同じ参照の版1は入力に含まれなかった。

この接続は試験用の送信元とUI担当に限る。利用者が実行中に送る補足の受付API、Pursuit・Agencyからの配送、再起動をまたぐ配送は別途検証が必要である。

## 再現に必要なファイル

- 基準測定には登録済みのコミットを別フォルダーに展開し、既存のlockfileで依存を導入する。[実行コード](live-runner.ts.txt)をコピー先のルートに `proactive-live.ts` として置く。試験の引数は課題JSON、出力先、モデル、反復数、並行数の順。測定時は `PROACTIVE_CALL_LIMIT=440`、`PROACTIVE_OBSERVATION_MS=30000`、`PROACTIVE_SCORE=1` を使用した。
- Steerの再現では別コピーを使い、同じTGZを試験ホストから `eumenes-steer` として解決できるようにしてから[差分](steer-host.patch)を適用する。[固定試験](steer-test.ts.txt)と[実モデル試験](steer-live-runner.ts.txt)は、コピー先のルートにそれぞれ `proactive-steering.test.ts` と `proactive-steering-live.ts` として置く。
- lockfileのSHA-256は `f4ad0c46c480ed739d7e25d33df1000698d1a5d1aa7ba92388288d0a590a0bdb`。Steer差分が確定コミットから作った未変更コピーに適用できることを確認した。
