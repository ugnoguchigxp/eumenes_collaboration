# CodexのWeb検索を背景調査へ接続

Collaborationの検証環境では、作成担当が公開情報を必要と判断すると、通常返答の後で独立した検索を開始する。検索には公開用の問いだけを送る。検索イベントが完了した場合に限り、返った公開URLと要約を成果物の作成担当へ渡す。検索できなかった場合はその状態を作成担当へ伝える。

Eumenesでは既存の `web_search` / `web_research` が使う検索取得経路に接続した。設定で明示的にCodexを選んだ場合に、Codexの組込みWeb検索へ渡せる。取得した候補は既存の本文取得・出典確認と同じ経路へ戻す。検索の推論は別の短い作業として実行し、保存済みモデル設定、期限、取消と結果の受理、使用量記録は既存のInferenceサービスを使用する。 [OpenAIのWeb検索モード](https://learn.chatgpt.com/docs/config-file/config-basic#web-search-mode)

## 検証

- 固定試験では、現在の検索ターンで完了した検索イベントだけを採用し、未発生・別ターンのイベント・取消後の結果を採用しないことを確認した。公開URLと要約が検索担当から作成担当へ届くこと、および検索失敗が作成担当に通知されることも確認した。
- 隔離した環境でLuna 6.0 `low` にSQLiteの公開仕様の確認を依頼した。作成担当は自発的に背景検索を選んだ。検索ターンは `cloud_agent_web_search_missing` で終了した。作成担当が出した出典付きのメモは検索成功に数えていない。初回の試行後に、検索失敗を作成担当へ明示するよう修正した。 [初回の実モデル試行](live.json)
- Codexの設定取得では `live`、提供元の能力照会ではWeb検索対応を返した。ターンに明示した `live`、`cached`、SDKの直接呼び出しでも、実際に検索が完了したイベントは確認できなかった。直接呼び出しでは、モデルが作業開始時の初期化ツールにも言及した。実モデルでの検索成功は未確認。
- Eumenes側は `EUMENES_CODEX_WEB_SEARCH=1` を明示した場合に限りこの経路を有効にする。標準設定では従来の検索を使う。今回の作業は隔離環境で行い、稼働サービスへの設定反映は行っていない。

[検索追加前の120秒測定](../proactive-luna-low-hard-review-120s/README.md)

Collaborationの固定試験205件と型検査、Eumenesの対象結合試験12件と作業コピーでの型検査が通過した。Eumenesのドメイン検証は、今回編集していない `createInference` と `createSavedBodies` の既存サイズ超過で止まった。隔離コピーで試験範囲を広げた際には、コピー側にない依存パッケージと既存のセッション権限テストで失敗した。セッション権限の失敗は変更前のHEADから展開した別の隔離コピーでも再現した。
