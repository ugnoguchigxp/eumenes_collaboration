# Skill Smithの配達とEvaluatorの分岐判定を確認した再測定

[前回](../proactive-luna-low-final/README.md)と同じ合成6課題を、現行相当と支援ありで各1回実行した。課題文には評価やスキル利用の指定を含めていない。両方式とも、隔離ホストからCodexの契約経路で `gpt-6-luna` の `low` を使用した。課題、順番、並行数、呼び出し上限、時間上限、採点基準を前回と揃えた。現行相当はEvaluatorとSkill Smithを無効にした。成果物は方式名を伏せて各課題4条件で採点し、手順の定型欄は別に確認した。 [事前登録](registration.json) · [課題と採点基準](../../../proactive/luna/cases.mjs)

## 原因と修正

- **Skill Smith**。前回は、本文を取得してもモデルが初期化、予算、追加資料を必要と判断して停止した。出力を構造化した後は、存在しない節IDや検証例の不足も確認した。新規生成を続けた中間測定では、適用可能な既存手順3件も、生成した検証例や判定を意味審査で拒否されていた。検証環境では、Context StillのMCPで取得した全文をLunaが読み、対象・目的・確定条件に適合する既存手順を選ぶ。Skill Smithの互換経路で本文を保持したスキルを組み立て、配達時に依存版を再照合する。選択後に本文が変わった場合の配達拒否も固定試験で確認した。 [取得後の失敗の切り分け](../proactive-luna-low-delivery/README.md) · [新規生成の中間測定](../proactive-luna-low-delivery-final/README.md)
- **Evaluator**。前回は、適合と判定した行が独立した指摘一覧では違反になっていた。個別試験では、違反と判定した行が別欄に転記されない逆の不一致も確認した。判定と指摘を行単位の一つの出力にまとめ、ホストが根拠位置を評価対象行に固定する。評価が完了した場合に確認済みの指摘を成果物の作成側に渡す。選択の指示も更新し、資料が揃っている場合でも、条件の組み合わせや例外を誤る影響があれば独立照合を検討できるようにした。 [行判定の個別試験](../proactive-luna-low-delivery/pilot-review-rows.json)

Skill Smithは機材貸出、欠品、公開判断で自発的に選ばれた。3件ともMCPの原文と依存版を照合したスキルが配達され、各成果物の冒頭に原文固有の定型欄が入った。配達までの時間は順に7.43秒、7.22秒、8.96秒。取消通知でも検索は選ばれたが、適用できる手順がなく、モデルを追加で呼ばずに成果物作成を続けた。

Evaluatorは対象と見込んだ3件で自発的に起動した。取消通知はa/cを適合、b/dのみを違反とした。予約判定はR1/R3を適合、R2/R4のみを違反とした。公開判断には現行の判定結果が記録されていなかったため、評価は未完了となった。成果物は手順と確定条件から作成し、公開に進める対象をP-03だけと判定した。

2文を超えた通常返答の5件も成果物まで完了した。機材貸出の支援ありの表題には、資料に明示されていない11月13日が補われた。固定の基本採点には日付の項目がない。各方式1回の測定であり、所要時間とモデル使用量は今回の観測値として扱う。
