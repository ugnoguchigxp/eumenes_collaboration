# Luna lowによる自発的支援の改修後試験

[前回の対照試験](../proactive-luna-low/README.md)と同じ合成6課題を、同じ隔離環境で各方式1回ずつ実行した。課題文、確定条件、採点基準、手順の本文は据え置いた。モデルは全工程で `gpt-6-luna`、推論設定は `low`。課題ごとの方式順、並行する課題数、時間と呼び出しの上限も前回と同じ。 [事前登録](registration.json) · [課題と採点基準](../../../proactive/luna/cases.mjs)

- 両方式で、通常返答の2文上限を目安として扱う。超過した文数は記録し、有効な支援依頼と成果物作成は継続する。
- 支援ありでは、MCPに登録した手順の題名を全課題に共通の一覧として提示する。検索や採用はモデルが判断する。手順本文はSkill SmithがMCPで取得し、版を照合してから配達する。
- Evaluatorには元の依頼と確定条件を渡す。トップレベルのレコード配列は、各レコードを個別のJSON Pointerとして評価範囲に含める。その他の項目も保持する。成果物を作るモデルには、指摘されなかった項目も元資料と照合するよう指示する。

通常返答は依頼開始から返答確定まで、完了は同じ起点から成果物確定までを測る。成果物は方式名を伏せ、課題ごとの4条件を各1点で採点する。未完了は0点とし、全試行の得点に含める。MCPの手順だけが指定する定型欄3件の反映は別に集計する。

両方式とも6課題を完了した。現行相当は24/24点、支援ありは23/24点。文数超過は現行相当3件、支援あり1件で、いずれも成果物を確定した。Evaluatorは取消通知の違反2件を特定した。Skill Smithは有用と見込んだ3課題すべてで選ばれ、対象外の取消通知でも選ばれた。選択4件は、本文取得前の辞退2件、意味審査の呼び出し枠不足1件、推論タイムアウト1件で配達に至らなかった。

この結果を受け、Skill Smithの選択指示に対象と用途の照合を加えた。生成担当には、適用候補の本文取得を一度の `disclose` にまとめ、生成と意味審査の枠を確保するよう指示した。 [集計](summary.json) · [全12試行](raw.jsonl) · [匿名化した成果物](blind.json) · [採点](grades.json) · [追加改修後の再測定](../proactive-luna-low-final/README.md)
