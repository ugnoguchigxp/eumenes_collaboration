# Luna 6.0 lowで支援が効く課題の難度探索

素のCodex Lunaと、Evaluator・Skill Smith・背景Web検索を利用できるLunaを、同じ隔離環境とCodex接続で比較した。どちらも `gpt-6-luna`、推論強度 `low`。EvaluatorはQuick、上限120秒。課題文にはツール名や利用指示を入れず、初回返答とともにモデルが選んだ支援だけを起動した。Web検索が選ばれた場合は、検索担当のターンで完了イベントが確認できたときに出典候補を引き継ぐ。Skill Smithが利用できる手順は、試験用Context Stillに登録した再利用可能な手順で、行ごとの答えは含まない。

初回は3候補を各条件2回測った。キャッシュで年齢計算の誤りが動作に波及したため、数値を入れ替え、引継ぎに必要な動作コードを主とする版を各条件3回測った。手順に別の数値を使った計算例を追加した。カレンダーは初回で全問正解が出たため、同じ課題と手順を固定して各条件2回追加した。全22試行で成果物が完成した。カレンダーの正解はPythonの `dateutil` とUTC変換、キャッシュは別実装で32行を照合した。キャッシュの現在齢はRFCの保守的な計算式、再利用可否は課題に示した運用ルールに従う。 [正解の照合記録](oracle-check.json) · [RFC 9111 §4.2.3](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2.3) · [RFC 5545 §3.3.10](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.10)

標準採点は、行の全項目が合い、同じIDに一つの判定がある場合に正答とした。動作判定版では素のLunaが補足表にIDを再掲したり、比較欄にコロンで注記したりして減点された。診断用に主表の動作コードだけを照合しても、素のLunaは14/24、支援ありは24/24だった。式あり版とRFC参照版は、難度調整の記録として残す。 [集計と試行別内訳](comparison.json) · [初回採点](screen/grades.json) · [動作判定版の採点](tune/grades.json) · [カレンダー再試行の採点](confirm/grades.json)

- **動作判定版**は支援ありの3回すべてでQuickとSkill Smithを選び、両方の結果が届いた。素のLunaが3回とも誤ったK-01とK-03について、Quickは毎回、現在齢33秒が共有鮮度32秒を越える場合は再検証、現在齢33秒が要求上限33秒と等しく共有鮮度34秒未満なら再利用、と指摘した。成果物の表で3回とも両方が正しく反映された。 [試行ログ](tune/raw.jsonl)
- **カレンダー版**は素のLunaが4回とも5/8。支援ありの4回は5、8、5、7行だった。QuickとSkill Smithの両方が届いた2回で、単発移動I-03と存在しない月末を飛ばすI-05が正答になった。窓の外からの移動I-07は追加試行でQuickも見落とした。自発選択に伴う結果であり、QuickとSkill Smithそれぞれの効果を分けるには追加の比較が必要。 [初回ログ](screen/raw.jsonl) · [追加ログ](confirm/raw.jsonl)
- **Web検索**はRFC参照版の2回で選ばれ、いずれも `cloud_agent_web_search_missing` だった。検索結果の受け渡しは0件。2回目の7/8にはQuickとContext Still由来の手順が届いた。Web検索結果が品質に与える効果は未測定。 [RFC参照版のログ](screen/raw.jsonl)
