# UI共同制作で次の一手を見つける開発試験

2026年11月12日。開発用6課題のみを使用した。Eumenes `4ed26d7f` の確定ソースを展開し、固定の依存で起動した隔離試験ホストで、通常のUI共同制作を各2ターン実行した。全6件で前後の作品定義・版・条件と出所が得られた。担当選択は基準測定と同じく固定した。制作と候補生成に `gpt-6.1-sol` の `low` を使用し、Codexのサブスクリプション経路で計36回呼び出した。 [採取条件](capture-registration.json) · [作品・条件の原記録](snapshots.jsonl.gz)

## 候補と根拠の確認

各課題で同じ会話・条件・最新の作品を渡し、「現行定義」と「現行定義に直前版を追加」の二通りで一案ずつ求めた。採点文、利用者役の追加発言、課題分類は候補モデルに渡さなかった。次の一手の具体性、実在する根拠、未確定条件の扱い、提案する時期を、候補と記録を突き合わせて暫定判定した。実際に提案を利用者に配送した試験や、人による独立採点は含まない。

初回は12案中4案で、作品ID・条件IDと資料IDの混同や資料内の相対位置のずれがあり、引用の検査で拒否した。引用を入力全体からのJSON Pointer一つに揃えた再測定では、12案すべてが引用の検査を通った。検査は位置が実在することを確かめ、引用が提案を裏付けるかは記録を照合して判断した。 [初回の出力](candidates-initial.jsonl) · [再測定の出力](candidates-pointer.jsonl)

| 課題 | 現行定義 | 直前版も追加 |
| --- | --- | --- |
| 社食の事前注文 | 確認表示に献立・数量・合計を引き継ぐ案。受取場所は未定、確認への移動と注文確定は別とした。 | 同じ判断。 |
| 町内会の連絡先 | 未提示の公開窓口に加え、画面が未確認の取り次ぎを約束している箇所を特定した。公開可否と取り次ぎの確認を次に置いた。 | 同じ未確認箇所を見つけ、取り次ぎを確約しない文面案も準備した。 |
| 授業アンケート | 確認中の待機を守り、次の一手は提示しなかった。 | 同じ判断。 |
| 美術館案内 | 見出し変更と開館時間の空欄を確認し、追加提案を控えた。 | 同じ判断。 |
| 駐車券精算 | 駐車時間と試算額を確認する文面を準備し、決済や現画面の変更を伴わない案にした。 | 同じ判断。 |
| 工作教室 | 対象年齢を決めつけず、未確認・可・不可の表示を準備した。年齢に合うことと最終的な申込可否の区別は残った。 | 年齢条件への合致と、未確定の他の参加条件を含む申込可否を区別した。 |

両方式とも準備4件・保留2件。今すぐ単独で知らせる判断は0件だった。町内会の例では、通常返答が触れなかった画面上の断定を具体的な箇所から拾えた。直前版を追加した6案に、直前版を引用したものはなかった。工作教室の区別も現行の条件記録から導けるため、次に試す準備は**最新の定義を出所付き条件と照合する方式**に絞る。通常ターンで出せる補足との差は、開発用課題でA+を用意して確認する。

再測定の候補呼出しは中央値13.9秒、最大16.2秒だった。隔離した候補推論の値であり、Queue待ちや表示までの時間は含まない。採用効果や自発提案を届ける時機の判断は正式比較に残る。

## 観測と正式比較の準備

隔離ホストに固定の単独メッセージを保存し、会話APIから取り出した文面と相対時刻を利用者役・採点者・集計が参照する試験を通した。通常返答の確定を起点とし、30秒以降や次の入力以降に届いた単独メッセージを分けて記録する。今回の正式比較は登録案の段階で、評価用24件には着手していない。 [観測コード](../../../proactive/observation.ts) · [正式比較の登録案](../../../proactive/protocol.json)

## 再現

1. [採取条件](capture-registration.json)のEumenesコミットを隔離先に展開し、固定の依存を導入する。既存の[採取コード](../../2026-11-11/proactive-mode-a/live-runner.ts.txt)に開発用 `development.json` を渡し、`PROACTIVE_CALL_LIMIT=48 PROACTIVE_OBSERVATION_MS=0 PROACTIVE_SCORE=0`、モデル `gpt-6.1-sol`、各1回、並行2件で採取する。保管済みの入力を使う場合は `snapshots.jsonl.gz` を展開する。
2. リポジトリルートから `bun eval/proactive/development.mjs <隔離Eumenes> <開発用snapshots.jsonl> <新規出力.jsonl>` を実行する。測定時の版は[初回の候補コード](development-initial.mjs.txt)と[引用形式変更後の候補コード](development-pointer.mjs.txt)に保管した。結果の先頭行に、実行時のコード・課題・入力のハッシュがある。
