# A+と背景準備の開発用6課題の比較

2026年11月12日。**背景準備で追加の根拠・確認結果が得られたのは2/6課題。工程3の条件である3課題に届かなかったため、背景準備の本体接続は見送る。**

## 比較条件

Eumenes `4ed26d7f` の隔離ホストと `ui.studio@5`、実モデル `gpt-6.1-sol` の `low` を使用した。最初の作成ターンを通常方式で行い、比較対象の更新ターンでは、既存の出力形式に補足欄を加えた。通常返答と同じ呼出しから補足を取得し、対応する返答の保存を確認できた場合に限り、試験会話へ添えた。6件すべてで更新ターンと補足の採否を確認できた。通常返答と補足は区別して保存し、補足が表示されたのは社食の1件。 [比較条件](comparison.json) · [A+の原記録](a-plus.jsonl.gz)

背景準備では、各A+試行で確定した**同じ作品定義と出所付き条件**を読み取った。A+の補足は候補モデルへ渡さなかった。A+の通常本文・補足の両方にない事実や確認結果を、作品または条件で裏付けられ、次の判断に使える場合だけ数えた。背景準備の比較文面は「次の一手」と「理由」を合わせたものとし、6件とも300字以内だった。課題につき最大一件。候補の表現差や未確認の案だけでは加点しなかった。 [背景準備の原記録](background.jsonl)

## 課題別の判定

| 課題 | A+で得られた情報 | 背景準備の差分と判定 |
| --- | --- | --- |
| 社食の事前注文 | 一覧と確認欄が縦に並ぶ状態を説明し、タブで切り替える案を補足した。 | 確認欄に献立・数量・合計を載せ、確定操作と分ける案。確認への導線が必要という判断は共通し、追加の案は新しい確認結果として数えなかった。 |
| 町内会の連絡先 | 実際の連絡先を載せず、事務局経由の案内を仮置きしたと回答した。 | **追加あり。** 事務局を経由する案内の中で、事務局が受け付けて各担当へ取り次ぐところまで記載されていた。宛先の公開可否と、担当への取り次ぎを実際に行えるかを別々に確かめる必要を特定した。根拠は現行定義の `/work/definition/children/3/body` と、経由の扱いが仮定になっている `/conditions/facts/2`。 |
| 授業アンケート | 利用者の確認が終わるまで待つと返答した。 | 同じく保留。 |
| 美術館案内 | 見出し変更を報告し、追加の制作提案は出さなかった。 | 完成の意図と開館時間の空欄を確認して保留。 |
| 駐車券精算 | 料金明細だけを表示し、利用者への確認は次に検討すると回答した。 | **追加あり。** 現行画面にある「駐車時間」と「精算金額（試算）」を確認対象として特定し、次に何を確認してもらうかを一件に絞った。根拠は `/work/definition/children/1` と `/work/definition/children/2`。 |
| 工作教室 | 対象年齢の範囲を尋ね、主催者の返事待ちなら未定として扱うと回答した。 | 対象内・対象外・条件未定の三状態を提案した。年齢が未確定という確認は共通し、三状態は新しい表示案なので加点しなかった。 |

背景準備は準備4件・保留2件で、自発提案の判断は0件。実モデルの呼出しは比較対象のA+が12回、背景準備が6回だった。採点は保管記録と実際の定義を照合した開発段階の判定。A+の採用可否、実ユーザーへの表示による手戻り削減、正式比較の評価用24件はこの試行の対象外。

## 再現と前段の確認

最初の試行では、基準版が出力形式を指示文に埋め込む経路を使っており、補足欄を追加する前に更新ターンが停止した。作成ターン6回の記録は保管し、比較から外した。指示文に載る出力形式を拡張するようにし、隔離ホストの固定応答で、既存の状態更新と通常返答を保って補足を添えられることを確認してから再測定した。 [初回の記録](a-plus-initial.jsonl.gz) · [初回のコード](supplement-trial-initial.mjs.txt)

隔離ホストと依存は[開発用の先行試験](../proactive-ui-development/README.md#再現)と同じものを使う。リポジトリルートで実行する。

```sh
bun eval/proactive/supplement-trial.mjs <隔離Eumenes> <新規A+出力.jsonl>
bun eval/proactive/development.mjs <隔離Eumenes> <A+出力.jsonl> <新規背景準備出力.jsonl> --current
```

背景準備の先頭行に、A+出力・実行コード・開発用課題のハッシュを保管した。評価用課題の実行入口はこの比較に含まない。

この測定で使ったA+の試験コードは [測定時のコード](supplement-trial.mjs.txt) に保管した。
