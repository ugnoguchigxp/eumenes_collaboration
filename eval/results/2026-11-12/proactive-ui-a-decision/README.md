# 現行方式Aで判断材料の不足と代替手段を区別する

2026年11月12日。町内会の通常返答で代替手段とその実施条件を示し、材料が揃っている場面では不要な提案を控えるため、共同制作の共通指示を見直した。 [共通指示](../../../../contexts/collaboration/rules.context.toml)

## 前回の出力を照合

- 町内会の両反復は、事務局経由の取り次ぎを仮定にした同じ初稿と条件から始まった。第1反復では、運営担当者に公開できる共通窓口・受付時間・取り次ぎ可否を尋ねることを未決事項として記録し、作品と返答をその窓口の公開後の案に揃えた。対面受付は、「公開可能な問い合わせ先が無い場合」を聞く追加質問の後に出た。
- 第2反復では、元の窓口を未決として残しながら、対面受付を別の仮案として記録した。対面受付の場所・日時と公開可否を運営担当者に確認する条件が、作品と最初の返答にあった。
- 社食の作品には注文確認欄と数量・合計の情報があり、受取場所が未定であることも分かった。第1反復は画面内移動の実装可否を実装担当に尋ねる案を付け、第2反復は既存の確認欄を短く伝えた。

町内会の第1反復では、作品・返答・未決事項がすべて当初の仮案を使うための確認に向いていた。前の指示は、未定事項を誰に確認するかと、使えない手段の代替案を示すことを別々に求めていたため、前者で返答を済ませられる読み方が残っていた。社食では、確認材料の不足と、将来の画面遷移の実装可否が別の問題だった。これは出力と指示の照合による原因仮説であり、モデル内部の判断過程は観測していない。 [前回の原記録](../proactive-ui-a-alternative/recheck.jsonl.gz) · [前回の指示](../proactive-ui-a-alternative/rules-recheck.context.toml.txt)

## 比較条件

前回のAの12試行を基準に、同じ開発用6件を各2反復した。Eumenes `4ed26d7f`、`gpt-6.1-sol` の `low`、保存した初稿・初回返答・出所付き条件、返答保存後30秒の観測枠、方式名を伏せたモデルの利用者役を揃えた。必要と判定されたときだけ、課題に登録した追加質問を一度送った。評価用24件と人による通し試験は実行していない。 [開発用6件](../../../proactive/development.json)

町内会では、元の窓口が未確定のままでも利用を検討できる方法と、その方法自体の確認先・実施条件を、最初の通常返答に各反復で示せたかを照合する。社食では、既存作品に確認材料がある状態で不要な提案が出なかったかを確認する。待機と完了は、返答に加えて作品定義と改訂番号を確認する。

## 最初の試験

最初の試験では、元の手段が使えない場合と、判断に使う項目が未定な場合を区別した。町内会の1反復は、紙の相談メモを手渡す案と、その受け付けの可否・日時・場所・担当を運営担当者に確認する条件を最初の返答に含めた。もう1反復は問い合わせ内容の準備にとどまり、追加質問が1回あった。社食の不要な提案は前回の1回から0回。待機・完了は各2/2だった。準備と受付の違いを踏まえ、別の方法を使った利用者がどの行動で止まっている工程を終えられるかまで考えるよう、共通指示を具体化した。 [最初の試験の原記録](initial.jsonl.gz) · [試験時の指示](rules-initial.context.toml.txt)

2回目も町内会は1/2反復で、もう1反復は相談内容の準備と元の窓口の確認にとどまった。社食では、既存の確認欄へスクロールする形でよいかを尋ねる不要な提案が1件出た。待機・完了は各2/2。3回目では、別の手段で共有を完了する一般例と、判断材料を既存の方法で利用できるときに参照先だけを返す一般例を共通指示に加えた。 [2回目の原記録](recheck.jsonl.gz) · [2回目の指示](rules-recheck.context.toml.txt)
