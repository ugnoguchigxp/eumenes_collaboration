# 評価用24課題での通常方式Aの比較

2026年11月12日。共同制作の通常返答を変更する前のAと、開発用6件で選んだ共通指示を使う見直し後のAを比較した。24課題を各方式で2反復し、96試行を記録した。**見直し後のAは採用を見送る。** 代替案と条件は増えた。追加質問は減らず、不要な提案と応答待ち時間が増え、完了を求められた場面にも悪化があった。 [開発用の検証](../proactive-ui-a-decision/README.md) · [評価用24課題](../../../proactive/holdout.json)

## 比較条件と採否基準

- Eumenes `4ed26d7f`、`binding:ui.studio@5`、`gpt-6.1-sol` の `low`、Codexサブスクリプション経路、返答確定後30秒の観測枠を揃える。試験用入口でUI担当を固定し、両方式で同じAgency設定を使う。前回の基準測定から初稿・初回返答・出所付き条件を取り出し、課題と反復が同じ組に再生する。初稿を取得できていなかった備品点検の第1反復には、第2反復の初稿を両方式で使う。 [初稿の原記録](../../2026-11-11/proactive-mode-a/mode-a-holdout.jsonl.gz)
- 方式名を伏せたモデルの利用者役が、通常返答・観測枠内の会話・作品にある判断材料を見て、登録された追加質問を必要時に一度送る。追加質問は実送信数を集計する。実行失敗や未完了は分母に残す。
- 阻害要因の6課題・各2反復では、最初の通常返答を直接読み、具体的な代替手段または確認までの暫定対応、その実施を左右する確認条件を別々に判定する。未定の表示だけでは加点しない。条件の値が確定するまで判断を止める案は、具体的な表示・手順と確認先・確認項目があれば暫定対応として数える。元の手段を使わずに目的を達成できる場合は、独立した代替手段として区別する。
- 待機と完了は、返答、作品差分、禁止された操作の有無を確かめる。別作品への切替を含む課題では、元の作品の保留と新しい作品への切替を確認する。完成課題は指定された変更だけが実際に行われたかを見る。
- 準備・阻害要因の課題では、同じ課題・反復を組にし、条件を保った上で追加質問か手戻りが減り、もう一方が増えなければ改善とする。完成・条件・追加質問・手戻りの悪化も同じ組で数える。改善課題数が悪化課題数を上回り、主指標と条件充足を維持し、待機・完了のどの反復にも新しい悪化がないことを採用候補の条件とする。追加質問と不要な提案の一方以上が減り、他方は増えず、待機・完了で不要な提案は0件とする。前景p95の増加は10%以内かつ1,000 ms以内。人の通し試験は計画にある本採用の別条件として扱う。 [採否基準](../../../../spec/proactive-collaboration-implementation-2026-11-11.md#採否)

## 待機と完了

待機の5課題・各2反復では、両方式とも提案せず、作品定義と改訂番号を保持した。別作品への切替は両方式の各2反復で `permission_revoked` により停止した。元の作品は改訂されず、新しい作品への切替と通常返答は確認できなかった。権限エラーの4試行を分母に含め、待機の指示と切替を合わせて確認できたのは両方式とも10/12だった。 [原記録](live.jsonl.gz)

完了・提案不要の6課題では、指定の変更を実施して余分な案内を添えずに終えたと、返答と作品差分で確認できたのは5/12から7/12だった。モデルの条件充足判定は7/12から9/12で、変更対象を尋ねて作品を編集しなかった試行にも一部で合格を付けていた。バス時刻表と朝市の一覧は、元の作品に指定されたラベルや重複文を特定できず、両方式の全反復で確認を求め、変更は完了しなかった。 [原記録](live.jsonl.gz)

プール案内では、見直し後の両反復が見出しだけを変えて終え、変更前の保存案内2件がなくなった。一方、花の展示案内の第1反復では、見直し後が一行化の報告に公開可否の確認を加えた。第2反復は変更前でモデル呼出しが失敗し、見直し後は一行への短縮を完了した。 [原記録](live.jsonl.gz)
